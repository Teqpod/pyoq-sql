Running statements

Diagnostics

Seeing what ran, counting it, and refusing too much of it.

These examples take three things as given:

  • database is an open database, from a pool you opened or from the framework you are inside
  • dsl is using(database)
  • TITLES and its columns come from your generated package

Your first query builds all three from nothing.

Everything here wraps a database and forwards to it. What you do not turn on is not wrapped, and costs nothing at all.

Seeing what ran

A sink is anything that takes the events. The one that collects them is enough to start with, and a logger or your own object works the same way.

Python
from pyoq.diagnostics import CollectingSink, EventPolicy, InstrumentedOperations

sink = CollectingSink()
watched = InstrumentedOperations(database, sink, EventPolicy(slow_after=0.5))

using(watched).select_from(TITLES).fetch_all()
sink.events

Every statement reports to your sink when it finishes or fails: what ran, how long it took, how many rows it touched. The policy decides how much detail:

Python
EventPolicy(
    include_values=True,          # never the ones marked sensitive
    include_failure_detail=True,  # a driver names the offending value in it
    slow_after=0.5,
)

Both default to off. A bound value can carry an argument you would not want in a log, and a driver’s error message often quotes it, so neither is included unless you ask.

Query shapes

A statement is fingerprinted into a shape: the SQL with its literals and comments removed, so the same query with different values is recognisably the same query.

Python
from pyoq.diagnostics import shape_cache_metrics

shape_cache_metrics()

That is what makes it possible to say “this query ran forty times in one request” rather than showing you forty distinct strings.

Counting a unit of work

Python
from pyoq.diagnostics import QueryBudget, QueryScope, ScopedOperations

scope = QueryScope(QueryBudget(maximum_queries=20, maximum_repeats=5))
counted = ScopedOperations(database, scope)

A scope counts what one unit of work runs. Exceed the budget and it raises QueryBudgetExceededError, naming the shape that did it.

maximum_repeats is the one that catches the classic mistake: the same query shape running once per row. Set it to a small number in tests and a loop that should have been one query fails the build instead of reaching production.

Metrics

Python
from pyoq.diagnostics import metrics_of

metrics_of(pool)   # open, idle, checked out, and how much is in use

Tracing

With the tracing extra, statements become OpenTelemetry spans:

Python
from pyoq.tracing import TracingSink

watched = InstrumentedOperations(database, TracingSink(tracer), EventPolicy())

A span is opened with the time the statement started rather than the time it finished, so the duration on the span is the duration of the statement.

Composing

The wrappers stack, because each is an operations object:

Python
database = ScopedOperations(
    InstrumentedOperations(base, sink, EventPolicy()),
    QueryScope(QueryBudget(maximum_repeats=5)),
)

Order matters only in what each one sees. A scope outside instrumentation counts statements that instrumentation reported; the other way round reports statements the scope allowed.
