pyoq commands

Every installed command, its options, and what it exits with.

The package installs two commands, and the first is also reachable as a module. Command line is the guide to using them; this is the reference.

Terminal
pyoq --help
pyoq --version
python -m pyoq generate

python -m pyoq runs exactly what pyoq runs.

pyoq

Text
pyoq [-h] [--version] {generate,inspect,snapshot,drift} ...
OptionWhat it does
--versionThe installed version, then exits.
-h, --helpUsage, then exits.

Every subcommand takes the same four options for finding and choosing configuration:

OptionWhat it does
--project-root PROJECT_ROOTThe directory holding pyproject.toml. Defaults to the working directory.
--config PYPROJECT_PATHA configuration file other than the one at the project root, named relative to it and inside it.
--profile SELECTED_PROFILEWhich profile to use, overriding selected-profile.
-h, --helpThe command’s own usage.

pyoq generate

Generates the typed database package.

Terminal
pyoq generate --project-root .
pyoq generate --check
pyoq generate --dry-run

Beyond the common options:

OptionWhat it does
--checkWrites nothing, and fails when the generated files are not current. This is the one for CI.
--dry-runShows the planned changes without writing anything.
--all-profilesGenerates every profile in profile layout as one atomic operation.

--check and --dry-run cannot be given together. Without either, the package is written: validated first, then replaced atomically, so a failure leaves what was there.

--profile and --all-profiles cannot be given together. Check and dry-run work with all profiles and identify each profile in their result.

pyoq inspect

Reads the configured database’s metadata and reports what it found.

Terminal
pyoq inspect
Text
inspected tables: 2; views: 1

Counts, not names. It is a check that the configuration reaches a database and that the database can be read. For the names, reflect the schema through pyoq.schema.

Takes the common options and nothing else.

pyoq snapshot

Records the database schema in the configured snapshot file, so generation can later run with no database at all.

Terminal
pyoq snapshot

Needs schema-snapshot configured. Takes the common options and nothing else.

pyoq drift

Compares the recorded snapshot against the database, and fails when they differ.

Terminal
pyoq drift

Takes the common options and nothing else. Reports what moved rather than only that something did.

pyoq-after-migration

Records the schema again and brings the generated package back in step, in that order, after a migration has been applied.

Terminal
alembic upgrade head && pyoq-after-migration
pyoq-after-migration path/to/project

It takes a project directory, or nothing and uses the working directory. It takes no options.

It is not an Alembic post-write hook. A post-write hook runs inside alembic revision, which writes a revision file while the database is still what it was, so recording there would record the schema the migration is about to replace. Alembic hands a hook the file it just wrote, and being handed a file is how this command detects that mistake: it refuses and says so, rather than recording a schema the migration has not reached.

The two places it belongs are after alembic upgrade, as above, or in env.py once the migrations have run, by calling after_migration_at.

It exits 0 when both steps succeeded and 1 when either failed, rather than using the codes below.

Exit codes

pyoq exits with one of these, which is what a shell reads from $?. They are ExitCode in Python.

CodeNameMeans
0SUCCESSThe command did what was asked.
1COMMAND_FAILEDIt ran and reported a failure, such as --check finding stale output or drift finding a difference.
2USAGEThe arguments were wrong.
3CONFIGURATIONConfiguration was missing, unreadable, or invalid.
4UNAVAILABLEThe command is not available for this dialect or this build.

1 is the one a CI step is usually reacting to: it means the command worked and the answer was no.
