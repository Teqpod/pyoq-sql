APIs

pyoq.fetching

Carrying out a fetch plan against a database.

Carrying out a resolved fetch plan against a database. Most applications reach this through the DSL; it is here for anyone driving a plan directly.

Running a plan

NameWhat it does
FetchExecutorRuns the statements a resolved plan owes. fetch(plan, *, where=None) returns every row the root describes, with its relations loaded.
AsyncFetchExecutorThe same, against a database that does not block.
FetchAssemblyCarrying out a resolved plan, apart from running anything, so the same traversal serves both executors.

What comes back

NameWhat it holds
FetchedRowOne row and everything fetched through it. read(table) gives it as the generated class; read_all(relation) gives the rows a relation resolved to; rows_of(relation) gives them untyped.
FetchColumnOne column a fetch reads, and what kind of value it holds.
FetchStatementOne level of a plan, as the statement that answers it.
RelationBlockWhere one table’s values sit in a row, and what hangs off them.

How a relation is brought back

NameWhat it describes
JoinedRelationA to-one relation this statement brings back in the same row.
NestedRelationA collection this statement returns beside its parent, as one value.
NestedJoinA table a collection reads alongside its own rows, as it comes back.
DeferredRelationA relation still owed a statement, and what its parents are keyed on.

Building the statements

NameWhat it does
root_statement(plan, graph, *, where=None)The statement answering a plan’s root and everything it carries along.
batch_statement(fetch, graph, keys)The statement bringing back the rows a batch of parent keys points at.
collection_for(fetch, carrying, *, parent=None, names=None)The collection a resolved fetch describes, as a node a dialect renders.
columns_of(graph, table)Every column a table has, in the order the table declares them.
projection_layout(widths)Where each table’s values sit once its columns are laid end to end.

Matching rows

NameWhat it does
join_condition(source, target)Matches a row to the one it points at, across every column of the key.
key_condition(columns, keys)Matches rows whose key columns hold any one of these keys.
batch_conditions(columns, batches)Turns batches already planned into the conditions that fetch them.
select_in_conditions(relation, columns, keys, *, maximum_parameters)One condition per statement this fetch will take.
KeyColumnA column a key is matched against.

Reading a collection back

NameWhat it does
decode_collection(payload, keys, types=())Reads one collection into a row of values per element.
hydrate_collection(payload, keys, construct, types=())Reads a collection into built rows, loaded and ready.
