pyoq.dsl

Every builder bound to a database, and what each method does.

pyoq.dsl is the surface you build statements on once you have an open database. A builder never touches the database: it returns a new builder each time, and only a fetch_ or execute call runs anything.

Every asynchronous class mirrors its synchronous one method for method, under the same name with Async in front. The only difference is that the methods which reach the database are awaited; the ones that build are not.

Python
from pyoq.dsl import using

dsl = using(database)

using

Python
using(operations: QueryOperations | AsyncQueryOperations) -> DslContext | AsyncDslContext

Binds a database to a builder. Hand it a synchronous set of operations and you get DslContext; hand it an asynchronous one and you get AsyncDslContext. Everything below hangs off the result.

Starting a statement

DslContext, and AsyncDslContext in the asynchronous form: a database to build against.

MethodWhat it does
select(*values)Starts a SELECT over the values named, which may be columns, expressions or aggregates.
select_from(table)Every column the table declares, without naming them one by one.
insert_into(table, *columns)Starts an INSERT. Naming columns fixes the order values are given in.
update(table)Starts an UPDATE. It has to say which rows it means before it will run.
delete_from(table)Starts a DELETE. It has to say which rows it means before it will run.
fetch(query)Runs a query, returning statement or routine call built the ordinary way, and reads it back the same way.

Building a select

BoundSelect, and AsyncBoundSelect: a SELECT that knows its database, with the builder’s own shape kept. Every method returns a new builder.

Where the rows come from

MethodWhat it does
from_(source)The table or subquery the rows come from.
distinct(enabled=True)Removes duplicate rows. Pass False to undo it.
with_(*common_tables)Attaches common table expressions the query then refers to.

Joining

Each of these returns a step that has to be told how the two sides line up.

MethodWhat it does
join(source)An inner join, qualified by the clause that follows it.
inner_join(source)The same, named explicitly.
left_join(source)Keeps every row on the left, with nulls where the right has no match.
right_join(source)Keeps every row on the right.
full_join(source)Keeps unmatched rows from both sides.
semi_join(source)Rows that have a match, without bringing the match back.
anti_join(source)Rows that have no match.
cross_join(source)Every combination, so no qualifying clause follows.
natural_join(source)Matched on every column both sides name the same way.
natural_left_join(source)The same, keeping unmatched rows on the left.
natural_right_join(source)The same, keeping unmatched rows on the right.
natural_full_join(source)The same, keeping unmatched rows from both sides.

cross_join and the natural_ family return a BoundSelect directly, because there is nothing left to say about how they match.

Qualifying a join

BoundJoinStep: a bound join waiting to be told how the two tables line up.

MethodWhat it does
on(condition)The predicate the rows are matched by.
using(*columns)Matched on columns both tables name the same way.
on_key(relation)Matched on the foreign key the schema already declares.

BoundSemiJoinStep, from semi_join and anti_join, offers on(condition) alone: there is no second row to bring back, so there is nothing to match by name.

Narrowing and grouping

MethodWhat it does
where(condition)Keeps rows the condition holds for. Called more than once, the conditions are combined with AND.
group_by(*expressions)Collapses rows that agree on the expressions given.
having(condition)Keeps groups the condition holds for, after grouping.
order_by(*terms)The order rows come back in.
limit(value)At most this many rows.
offset(value)Skips this many rows first.

Completing a query

BoundQuery, and AsyncBoundQuery: a query and the database it will run against. order_by, limit and offset are here as well, so they can be applied after a set operation.

Inspecting it

MethodWhat it does
sql()Returns dialect-specific SQL with bound values represented by placeholders. Performs no I/O.
compile()Returns CompiledQuery, including SQL, parameters, sensitive indexes, statement kind, and result types. Performs no I/O.

These methods are synchronous on AsyncBoundQuery because compilation does not reach a database. Policy wrappers still rewrite or reject the statement at this boundary. Diagnostics and query budgets observe execution only, so neither is recorded here.

Combining whole queries

MethodWhat it does
union(other)Rows from either query, duplicates removed.
union_all(other)Rows from either query, duplicates kept.
intersect(other)Rows both queries return.
except_(other)Rows the first returns and the second does not.

Running it

These are the methods that reach the database. In the asynchronous form each one is awaited.

MethodWhat it does
fetch_all()Every row, with the names they came back under.
fetch_one()Exactly one row, because that is what the caller said to expect. Raises when there is not exactly one.
fetch_optional()One row, or None when there are none.
fetch_optional_into(factory)One row built by the caller’s own type, or nothing.
fetch_value()The single column of the single row. Available only when the query selects exactly one column.

Writing

Inserting

BoundInsert: an INSERT and the database it will run against.

MethodWhat it does
values(*values)One row, given in the order the columns were named.
values_many(rows)Many rows from one iterable, sent as one statement.
on_conflict_do_nothing(*columns)Skips a row that would collide on the columns given.
on_conflict_do_update(*columns)Updates the existing row instead, returning the builder that says how.

BoundConflictUpdate, from on_conflict_do_update:

MethodWhat it does
set(column, value)What the existing row becomes.
where(condition)Applies the update only to rows the condition holds for.

Updating

BoundUpdate: an UPDATE, which has to say which rows it means.

MethodWhat it does
set(column, value)One column and what it becomes.
set_values(values, *columns)Several columns at once, taken from a value the caller already has.
where(condition)Which rows are affected.
all_rows()Says that every row is meant, which is how a statement without a where is allowed to run.

Deleting

BoundDelete: a DELETE, which has to say which rows it means. It offers where(condition) and all_rows(), with the same meanings.

Finishing a write

BoundMutation: what every bound write can do, whatever it is writing.

MethodWhat it does
sql()Returns dialect-specific SQL with placeholders without executing.
compile()Returns the complete immutable compiled statement without executing.
execute()How many rows the database says it wrote.
returning_all()Every column the table declares, without listing them.
returning(*values)The columns or expressions named.

BoundReturning, from either of those, reads rows back with the same fetch_all, fetch_one, fetch_optional, fetch_optional_into and fetch_value as a query. It also exposes the same non-executing sql() and compile() inspection methods as a mutation.

Reading results

Result: the rows a query returned, and the labels they came back under.

MethodWhat it does
to_list()The rows as a list of tuples.
to_tuple()The rows as a tuple of tuples.
map(mapper)One value per row, built by whatever the caller passes.
into(factory)Each row spread across a constructor, in the order it was selected.
to_dicts()Rows keyed by the names they came back under.
to_dict()Exactly one row, keyed by the names it came back under.
first()The row at the front, keyed the way every row here is, or None.
one()Exactly one row, because that is what the caller said to expect.

Row: one row, and the names it came back under.

MethodWhat it does
to_tuple()The row as the tuple it was typed as.
to_list()The same values as a list.
to_dict()Keyed by the names it came back under.
into(factory)Spread across a constructor, in the order it was selected.

The asynchronous names

They are exported from pyoq.dsl and, for a caller wanting only the asynchronous surface, from pyoq.dsl.aio:

AsyncBoundConflictUpdate, AsyncBoundDelete, AsyncBoundInsert, AsyncBoundJoinStep, AsyncBoundMutation, AsyncBoundQuery, AsyncBoundReturning, AsyncBoundSelect, AsyncBoundSemiJoinStep, AsyncBoundUpdate, AsyncDslContext

Every one has the same methods as its synchronous twin: AsyncDslContext, AsyncBoundSelect, AsyncBoundJoinStep, AsyncBoundSemiJoinStep, AsyncBoundQuery, AsyncBoundInsert, AsyncBoundConflictUpdate, AsyncBoundUpdate, AsyncBoundDelete, AsyncBoundMutation and AsyncBoundReturning. Only the methods that reach the database differ, and they are awaited.
