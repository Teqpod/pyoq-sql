APIs

pyoq.relations

Relation facts derived from a schema, and the plans that fetch them.

Typed relation facts derived from a schema, and the plans that fetch through them. See Relations for the workflow.

The graph

NameWhat it does
derive_relations(snapshot)Reads every foreign key in a snapshot from both of its sides.
table_relations(catalog, schema, table)The foreign keys one table declares, from both sides.
build_relation_graph(...)The graph those relations form.
RelationGraphEvery relation, reachable by table: table, relations_from, to_one_from, to_many_from, target_table.
TypedRelationOne relation, with the types on both ends.

Planning a fetch

A plan says what to bring back beyond the rows themselves, and how.

NameWhat it does
FetchPlanEverything one query fetches beyond its own rows. describe() reads it back as lines, so it can be seen before it runs.
FetchRequestOne relation to fetch, and whatever is fetched through it.
FetchStrategyHow the rows are brought back: JOINED, NESTED, SELECT_IN, AUTO.
FetchJoinA table a collection reads alongside the one its relation names.
FetchOrderOne term a collection is ordered by, and which way it runs.
by_column(name, *, descending=False)Orders a collection by one of the related table’s own columns.
by_expression(name, *, descending=False)Orders it by an expression, under the name a plan reports.

Resolving one

AUTO is decided here, against what the dialect can actually do.

NameWhat it does
resolve_fetch_plan(plan, capabilities)Turns a plan into one this dialect can carry out.
validate_fetch_plan(plan, graph, *, maximum_depth=8)Refuses a plan describing a fetch the schema cannot perform.
FetchCapabilitiesWhat one dialect can do: nested_collections, ordered_nested_collections.
plan_key_batches(relation, keys, *, maximum_parameters)Splits keys into the fewest statements a parameter limit allows.
DEFAULT_KEY_LIMITHow many keys go into one statement by default.
