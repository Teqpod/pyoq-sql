Frameworks

FastAPI

Lifespan owned pools and typed request dependencies.

The pool belongs to the application’s lifespan: opened once when the app starts, closed once when it stops. A route asks for a database and gets one.

Terminal
pip install "pyoq-sql[fastapi]"

Opening the database

Python
from fastapi import FastAPI
from pyoq.fastapi import SyncDatabase, database_lifespan
from pyoq.query.sqlite import SQLiteConnectionFactory, SQLiteExecutor, SQLitePool

def open_notes() -> SyncDatabase:
    pool = SQLitePool(SQLiteConnectionFactory(path))
    return SyncDatabase(SQLiteExecutor(pool), pool.close)

app = FastAPI(lifespan=database_lifespan(synchronous={"default": open_notes}))

You hand over how to open it and how to close it. The lifespan does the rest, including closing what it opened when startup fails halfway.

Asynchronously it is the same shape with AsyncDatabase and asynchronous={...}. The asynchronous guide shows the complete PostgreSQL setup, and Connections and pools covers sizing.

Generated packages for several databases

Code generation stays outside the web process. Configure profile layout in pyproject.toml, run pyoq generate --all-profiles, and import each database’s descriptors from its own package. Use the same names for generation profiles and lifespan aliases so the relationship remains obvious:

Python
from generated.database.tables import CUSTOMER
from generated.reporting.tables import SALES_TOTAL

app = FastAPI(
    lifespan=database_lifespan(
        synchronous={
            "default": open_application_database,
            "reporting": open_reporting_database,
        }
    )
)

pyoq generate --profile reporting refreshes only generated.reporting. The configuration guide defines profile layout and the generation guide covers atomic all-profile publication. FastAPI uses those shared packages and does not run generation during application startup.

In a route

Python
from typing import Annotated
from fastapi import Depends
from pyoq import fastapi as pyoq_fastapi
from pyoq.query.execution import QueryOperations

Database = Annotated[QueryOperations, Depends(pyoq_fastapi.database())]

@app.get("/notes")
def list_notes(database: Database) -> dict[str, object]:
    return {"notes": using(database).select_from(NOTES).fetch_all().to_dicts()}

The alias is a normal dependency, so several databases are several annotations. For example, pyoq_fastapi.database("reporting") selects the runtime database that corresponds to the reporting generated package.

A route that writes

Python
Transaction = Annotated[QueryOperations, Depends(pyoq_fastapi.transaction())]

@app.post("/notes")
def add_note(database: Transaction) -> dict[str, int]:
    return {"written": using(database).insert_into(...).values(...).execute()}

transaction() opens one for the request and ends it when the route returns. A route that raises rolls back. An asynchronous route takes async_transaction().

Budgets per request

Python
from pyoq.diagnostics import QueryBudget, QueryScope, ScopedOperations

scope = QueryScope(QueryBudget(maximum_queries=20))
counted = ScopedOperations(database, scope)

Wrap the dependency and a route that runs a query per row fails loudly rather than slowly.

Testing

Python
app.dependency_overrides[pyoq_fastapi.database()] = lambda: substitute

The dependency is the key, so a test swaps the database the way it swaps any other dependency. No global to reset, and nothing to remember to undo. See Testing applications for the broader test split.
