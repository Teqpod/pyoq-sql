Your data

Column types

What a column holds, and reading it back as that.

These examples take three things as given:

  • database is an open database, from a pool you opened or from the framework you are inside
  • dsl is using(database)
  • TITLES and its columns come from your generated package

Your first query builds all three from nothing.

A generated column carries three things: the Python type it holds, the family it belongs to, and whether it may be null.

Python
TITLES.PRICE     # ColumnDescriptor[Decimal]
TITLES.COUNTRY   # ColumnDescriptor[str | None]

The mapping

DatabasePython
booleanbool
smallint, integer, bigintint
numeric, decimalDecimal
real, doublefloat
text, varchar, charstr
bytea, blobbytes

json, jsonbany JSON value

arraytuple[T, ...] of the element type

A nullable column is that type or None, and the type checker will make you handle it.

An array reads back as a tuple rather than the driver’s list, because a row is a value and a value that can be edited under you is not one. That is also why an array is counted from zero, the way the tuple you get back is, and PyOQ writes the difference out to the dialect instead of leaving you to remember it. See Expressions.

Read back as what it is

A driver hands back whatever it stores. A Decimal column on SQLite comes back as a float, a UUID as text, JSON as a string. PyOQ decodes each value to the type the column was declared to hold, so TITLES.PRICE gives you a Decimal on every backend.

Python
row = dsl.select_from(TITLES).fetch_one()
row.to_dict()["price"]    # Decimal('12.50'), not 12.5

That is why the generated descriptor carries the type and not just the family: an integer, a float, and a decimal are one family and three types, and only the type says how to read it back.

Values on the way in

The same in reverse. You pass a UUID, a Decimal, a timedelta, or a dict, and PyOQ binds what the driver accepts. You never write str(value) to make something fit.

Under Django this goes further: a value is bound through the field Django itself would use, so a row PyOQ writes is a row the ORM can read and filter on. See Django.

Enums

A database enum becomes a real Python enum, and a column of that type is typed as it:

Python
from generated.enums import TitleStatus

dsl.select_from(TITLES).where(TITLES.STATUS.eq(TitleStatus.PUBLISHED))

Domains

A domain is a named type with rules attached. Generation keeps that distinction with NewType, over the Python type it is written on. A domain such as

SQL
CREATE DOMAIN email_address AS text NOT NULL CHECK (VALUE LIKE '%@%')

produces a distinct EmailAddress type over str. A domain over numeric(12, 2) is a distinct type over Decimal, precision and all.

Python
from generated.domains import EmailAddress

address = EmailAddress("reader@example.test")
dsl.select(USERS.ID).from_(USERS).where(USERS.EMAIL.eq(address))

At runtime a NewType value is its base value, so drivers need no wrapper or conversion. Static checks still prevent an ordinary string or another string domain from being used where EmailAddress is required.

The schema keeps the domain’s name as well as its base type, because a schema that forgot it would no longer describe the database it was read from.

A domain that forbids null makes every column of it not nullable, whatever the column itself declared, because the server refuses a null there either way. A schema that called such a column optional would be describing something the database will not do.

PostgreSQL has domains. SQLite and MySQL have none.

Row identity

Hydration needs to know when two rows are the same row. It takes the primary key when there is one, and a unique key when there is not. When a table has neither, PyOQ refuses to hydrate rather than inventing an identity that would silently merge distinct rows.
