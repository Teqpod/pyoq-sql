Running statements

Asynchronous execution

Using the asynchronous pools and the awaited DSL without hidden blocking.

The asynchronous API has the same query model as the synchronous API. Building a statement is still ordinary, non-blocking Python. Only connection work and result reading are awaited.

PostgreSQL and MySQL have asynchronous executors. SQLite uses Python’s synchronous driver, so run it through the synchronous API or isolate it in a worker thread owned by your application.

Open an asynchronous database

Python
from pyoq.query.execution import PoolPolicy
from pyoq.query.postgres.aio import (
    PostgresAsyncConnectionFactory,
    PostgresAsyncExecutor,
    PostgresAsyncPool,
)

policy = PoolPolicy(minimum_size=1, maximum_size=8, checkout_timeout=2.0)

async with PostgresAsyncPool(
    PostgresAsyncConnectionFactory(database_url),
    policy,
) as pool:
    database = PostgresAsyncExecutor(pool)
    await serve(database)

An asynchronous pool must be opened before use. async with opens it and guarantees closure. If lifecycle code cannot use a context manager, call await pool.open() once and await pool.close() during shutdown.

For MySQL, use MySQLAsyncConnectionFactory, MySQLAsyncPool, and MySQLAsyncExecutor from pyoq.query.mysql.aio.

Use the same DSL

Python
from pyoq.dsl import using

dsl = using(database)

rows = await (
    dsl.select(TITLES.ID, TITLES.NAME)
    .from_(TITLES)
    .order_by(TITLES.ID)
    .fetch_all()
)

using() is overloaded. An asynchronous executor produces an AsyncDslContext, so the final operation is awaitable and the row type remains the same. There is no separate query syntax to learn.

Writes are awaited at the terminal operation:

Python
written = await (
    dsl.insert_into(TITLES, TITLES.NAME)
    .values("A Guide")
    .execute()
)

Transactions and savepoints

Use the operations object yielded by the transaction. It is tied to the one checked-out connection that owns the transaction:

Python
async with database.transaction() as transaction:
    transactional = using(transaction)
    await transactional.insert_into(TITLES, TITLES.NAME).values("A Guide").execute()

    async with transaction.savepoint() as savepoint:
        await using(savepoint).update(TITLES).set(
            TITLES.NAME,
            "A Revised Guide",
        ).where(TITLES.ID.eq(1)).execute()

Calling the outer executor inside the block can borrow a different connection. That statement would not belong to the transaction. The same rule applies to the synchronous API.

Streaming

Python
from pyoq.query.execution import StreamPolicy

async with database.stream(statement, policy=StreamPolicy(batch_size=500)) as rows:
    async for row in rows:
        await consume(row)

The stream holds a connection. Keep per-row work bounded, and move slow or unrelated I/O after the stream when possible. Cancellation and timeout controls are described in Transactions and streaming.

Framework ownership

FastAPI opens asynchronous pools in its lifespan. Sanic opens one per worker after workers split. Do not create a pool inside a route or handler.

Django connections are synchronous. In an async Django view, wrap the complete synchronous database operation with sync_to_async as shown in the Django guide. Mixing a Django transaction with a separate async pool would create two independent connection and transaction scopes.

Avoid hidden blocking

Do not call a synchronous executor from the event-loop thread. The query may be fast, but checkout, network I/O, and result decoding still block that thread. Use the asynchronous executor for PostgreSQL or MySQL, or move the complete synchronous unit of work to a worker thread.
