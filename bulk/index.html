Writing

Bulk writes

Writing more rows than one statement can carry.

These examples take three things as given:

  • database is an open database, from a pool you opened or from the framework you are inside
  • dsl is using(database)
  • TITLES and its columns come from your generated package

Your first query builds all three from nothing.

Every database has a limit on how many parameters one statement may bind. SQLite defaults to 999, PostgreSQL and MySQL to 65535. Write enough rows and you cross it.

PyOQ does not silently chunk behind your back, and it does not fail at the driver either. You ask for a plan.

Planning

Python
plan = database.plan_bulk(statement)

plan.statement_count   # how many statements it becomes
plan.input_rows        # how many rows you gave it
plan.row_counts        # the rows in each chunk

The plan says how the write will be split for this dialect, given its parameter limit and the number of columns you are writing. Nothing has run yet, so you can look at it, log it, or refuse it.

Running it

Python
result = database.execute_bulk(statement)

result.rows_affected
result.statement_count

execute_bulk plans and runs in one call. Each chunk is a real multi-row statement, so a hundred thousand rows becomes a manageable number of statements rather than a hundred thousand of them.

Inside a transaction

Bulk writes are not automatically atomic across chunks. When all of it must land or none of it, say so:

Python
with database.transaction() as transaction:
    transaction.execute_bulk(statement)

Use the yielded operations object. It owns the connection and transaction; calling database.execute_bulk inside the block could borrow another connection.

That is a deliberate choice rather than a default, because for a large import the right answer is often the opposite: commit as you go so a failure halfway does not undo an hour of work.

Choosing a size

The planner uses the dialect’s limit, which is the number that actually matters. Where you want a smaller one, to keep transactions short, or to stay under a proxy’s timeout, the dialect’s capabilities take a lower limit:

Python
from pyoq.query.sqlite import SQLiteCapabilities, SQLiteCompiler

compiler = SQLiteCompiler(SQLiteCapabilities(maximum_parameters=200))

Reading a plan before trusting it

Python
plan = database.plan_bulk(statement)
if plan.statement_count > 50:
    raise TooMuch(plan.statement_count)
database.execute_bulk(statement)

Worth doing on a path where the row count comes from a request. It turns a surprise into a decision.
