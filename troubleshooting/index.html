Troubleshooting

What went wrong, what it means, and what to do about it.

Every error PyOQ raises is deliberate and named. Errors lists them; this page is the ones people actually hit.

The generated package is not there

pyoq generate writes only the files it owns, into the directory codegen-directory names. If nothing appeared, the command ran against a different project root than you think.

Terminal
pyoq generate --project-root .

Every command takes --project-root, and everything else is resolved from it.

A generated import fails

A generated package is replaced whole, so a half-written one is not a state it reaches. An ImportError from inside it means the package on disk is from an older schema than the code importing it. Regenerate.

If it persists, check that codegen-package matches where the directory actually sits on the import path. The directory and the importable name are two settings and they have to agree.

In profile layout, include the generated package segment in the import. For example, codegen-package = "generated" and codegen-name = "database" produce generated.database, not generated.

Generation says the package is not current

That is pyoq generate --check doing its job. It writes nothing. Run pyoq generate to bring the package up to date, and commit the result.

For profile layout, use --profile NAME to repair one package or --all-profiles to check and publish every configured package together.

In CI, record a snapshot so the check needs no database at all. See Snapshots and drift.

Drift after a migration

pyoq drift failing means the recorded schema and the database disagree. That is expected right after a migration and is what the migration hook is for.

Python
from pyoq.migrations import after_migration_at

after_migration_at(".")

The hook records the snapshot before generating. See Migration lifecycle before wiring it into a migration tool.

A capability error

PyOQ refuses an operation the dialect cannot perform, while the query is being compiled, rather than sending SQL that would fail.

Text
SQLite has no array type; hold a collection as JSON or in a table of its own

The message names what the dialect has not got. What each dialect can do says which operations each one supports, and every entry there was taken from a running server.

A type checker disagrees with a value

If a checker says a column is a Decimal and you are handed a float, that is a defect and not something to work around. PyOQ derives the Python type an expression answers with from the expression itself and decodes to it.

Check first that the column’s declared type is what you think: a generated descriptor carries it, and reading it back is what the decoder uses.

A statement is refused by a policy

Policies are applied before compilation, so a refusal happens while the statement is built.

Text
policy refused table: audit_log

If the refusal is wrong, the fix is the policy. If it is right but you need past it once, there is a scoped, audited bypass. See Policies.

Too many statements

Diagnostics count statements per unit of work and report repeated shapes, which turns “it feels slow” into a number. A budget refuses a unit of work that runs more than you meant to allow. See Diagnostics and Performance.

The pool times out

ConnectionPoolTimeoutError means every allowed connection remained checked out for the pool’s timeout. Inspect pool.stats, then look for a stream or transaction context that spans unrelated work. Increasing the pool can move the queue into the database without fixing the cause. See Connections and pools.

A procedure answered with more than one result set

MySQL allows it; PyOQ refuses it rather than reading the first and discarding the rest, because a dropped result set is a silent one.

Have the procedure answer with one result set, or read the others in statements of their own.

Nothing here matches

Every error type PyOQ raises inherits from one base, so a catch-all is available while you find out which one it is.

Python
from pyoq.errors import PyOQError
