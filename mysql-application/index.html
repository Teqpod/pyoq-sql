Running statements

MySQL without a framework

A larger Python application with generated types and one process-owned pool.

This guide builds a multi-module Python application without Django, FastAPI, Sanic, or another framework. The application owns one MySQL pool for the life of its process. Each operation borrows a connection, and each transaction keeps one connection until its block exits.

The ownership model

The entry point is the composition root. It creates infrastructure, passes dependencies inward, and closes infrastructure after application work stops. Nothing opens a connection while modules are imported.

Install the project

Terminal
uv add "pyoq-sql[mysql]"
uv add --dev ruff mypy pyright pytest

The MySQL extra installs PyMySQL. A machine running the application needs the wheel and driver, but it does not need Rust.

Organise the modules

PathResponsibility
pyproject.tomlpackage metadata, generation destination, and schema profile
src/application/repositories/accounts.pyaccount persistence statements
src/application/services/accounts.pytransaction boundary and application rules
src/application/main.pyprocess composition and shutdown
src/application/generated_database/generated tables, rows, writes, relations, and routines
tests/integration/test_accounts.pybehavior against a real MySQL schema

The generated directory is entirely owned by PyOQ. Keep application code in the surrounding modules, never inside that directory.

Configure generation

Configuration
[project]
name = "account-service"
version = "1.0.0"
requires-python = ">=3.11"
dependencies = [
    "pyoq-sql[mysql]>=1.0.0",
]

[project.scripts]
account-service = "application.main:main"

[tool.pyoq]
codegen-directory = "src/application/generated_database"
codegen-package = "application.generated_database"
selected-profile = "default"

[tool.pyoq.profiles.default]
dialect = "mysql"
host = "127.0.0.1"
port = 3306
database = "${MYSQL_DATABASE}"
username = "${MYSQL_USERNAME}"
password = "${MYSQL_PASSWORD}"
minimum-pool-size = 1
maximum-pool-size = 10
pool-checkout-timeout = 3.0

Export the secret values before generation or application startup:

Terminal
export MYSQL_DATABASE="application"
export MYSQL_USERNAME="application_user"
export MYSQL_PASSWORD="replace-with-a-secret"

PyOQ percent-encodes credentials when it constructs the internal data source name. A setting in the exact ${VARIABLE_NAME} form comes from the process environment; any other string is literal. MySQL data source names do not accept query or fragment options. Pool behavior belongs in the profile, not in URL parameters.

Apply schema changes with the migration tool that owns your schema, then generate the package:

Terminal
uv run pyoq generate --project-root .
uv run pyoq generate --project-root . --check

Use --check in CI. It reports generated drift without rewriting files. A recorded schema snapshot can make the check independent of database access.

The remaining examples assume the schema generated an ACCOUNTS table descriptor and an AccountsRow value with these columns:

SQL
CREATE TABLE accounts (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(320) NOT NULL UNIQUE,
    display_name VARCHAR(120) NOT NULL,
    active BOOLEAN NOT NULL DEFAULT TRUE
);

Keep connection behavior in the profile

connect() resolves the profile fields and pool limits before opening the pool. Sensitive values stay redacted inside the configuration layer and are revealed only while constructing the connection. Do not log connection data. An explicit pool_policy=PoolPolicy(...) can replace the profile policy for a special process, but the ordinary application path needs no repeated settings.

Own the pool in one lifecycle

Python
from pyoq import connect

from application.generated_database.tables import ACCOUNTS


with connect(
    profile="default",
) as database:
    rows = database.select_from(ACCOUNTS).limit(10).fetch_all()

The context creates the configured MySQL pool, yields a typed Database, and closes the pool on every exit path. The database is safe to share across services in the same process because each operation borrows a connection. Do not enter connect() in every repository, job, or function.

minimum_size connections open with the pool. Additional connections open on demand up to maximum_size. Startup therefore proves at least one connection can be made. Set minimum_size=0 only when lazy connection establishment is a deliberate choice.

Connect directly when there is no project profile

An installed program may not ship its source pyproject.toml. Pass the data source and dialect explicitly in that case:

Python
from pyoq import Dialect, connect
from pyoq.config import DataSourceName
from pyoq.query.execution import PoolPolicy


database_url = DataSourceName("${MYSQL_DATABASE_URL}")
with connect(
    database_url,
    dialect=Dialect.MYSQL,
    pool_policy=PoolPolicy(maximum_size=10),
) as database:
    run_application(database)

Profile arguments and a direct data source cannot be combined. This keeps one authoritative connection source for each lifecycle.

Make repositories transaction-compatible

A repository needs query operations, not ownership of the pool. The same repository can therefore use the process executor for an independent statement or the operations yielded by a transaction.

src/application/repositories/accounts.py:

Python
from pyoq.dsl import using
from pyoq.query import insert_into
from pyoq.query.execution import QueryOperations

from application.generated_database.rows import AccountsRow
from application.generated_database.tables import ACCOUNTS


class AccountRepository:
    __slots__ = ("_operations",)

    def __init__(self, operations: QueryOperations) -> None:
        self._operations = operations

    def find_by_id(self, account_id: int) -> AccountsRow | None:
        return (
            using(self._operations)
            .select_from(ACCOUNTS)
            .where(ACCOUNTS.ID.eq(account_id))
            .fetch_optional_into(AccountsRow)
        )

    def create(self, email: str, display_name: str) -> int:
        statement = insert_into(
            ACCOUNTS,
            ACCOUNTS.EMAIL,
            ACCOUNTS.DISPLAY_NAME,
        ).values(email, display_name)
        result = self._operations.execute(statement)
        account_id = result.last_inserted_id
        if not isinstance(account_id, int):
            raise RuntimeError("MySQL did not return an account identifier")
        return account_id

    def rename(self, account_id: int, display_name: str) -> int:
        return (
            using(self._operations)
            .update(ACCOUNTS)
            .set(ACCOUNTS.DISPLAY_NAME, display_name)
            .where(ACCOUNTS.ID.eq(account_id))
            .execute()
        )

MySQL does not support INSERT ... RETURNING. Read the generated identifier from ExecuteResult.last_inserted_id, then issue a separate select if the complete row is required. Do both in one transaction when they must observe one unit of work.

Put transactions in the service layer

The service decides which statements must commit or roll back together. The repository only describes and executes persistence operations.

src/application/services/accounts.py:

Python
from pyoq import Database

from application.generated_database.rows import AccountsRow
from application.repositories.accounts import AccountRepository


class AccountService:
    __slots__ = ("_database",)

    def __init__(self, database: Database) -> None:
        self._database = database

    def register(self, email: str, display_name: str) -> AccountsRow:
        with self._database.transaction() as transaction:
            repository = AccountRepository(transaction)
            account_id = repository.create(email, display_name)
            account = repository.find_by_id(account_id)
            if account is None:
                raise RuntimeError("created account could not be read")
            return account

    def rename(self, account_id: int, display_name: str) -> AccountsRow:
        with self._database.transaction() as transaction:
            repository = AccountRepository(transaction)
            if repository.rename(account_id, display_name) != 1:
                raise LookupError(f"account does not exist: {account_id}")
            account = repository.find_by_id(account_id)
            if account is None:
                raise RuntimeError("renamed account could not be read")
            return account

Always construct the repository with transaction inside the block. Calling the outer database there can borrow another connection, and that statement would not belong to the transaction.

Leaving the block normally commits. An exception rolls it back. Nested transaction work uses transaction.savepoint() rather than checking out a second connection.

Start and stop the application

src/application/main.py:

Python
from pyoq import connect

from application.services.accounts import AccountService


def main() -> None:
    with connect(profile="default") as database:
        accounts = AccountService(database)
        account = accounts.register("reader@example.test", "Example Reader")
        print(account.id, account.email)


if __name__ == "__main__":
    main()

The context remains open for the complete application run. Normal completion, an exception, or KeyboardInterrupt all leave the context and close the pool. Closing is idempotent. Idle connections close immediately, while checked-out connections close when their lease returns.

For a daemon or queue worker, keep the same outer lifecycle and make the stop signal end the work loop:

Python
from threading import Event

from pyoq import Database


def run_worker(database: Database, stopping: Event) -> None:
    while not stopping.is_set():
        job = receive_next_job()
        with database.transaction() as transaction:
            process_job(job, transaction)

Register signal handlers in the entry point. They should set stopping; the entry point then leaves connect after current work unwinds. Do not close the pool from a signal handler while another thread may be using it.

Stream large reads

A normal fetch_all() holds every decoded row. Use a stream when the result must stay bounded in memory:

Python
from pyoq import Database
from pyoq.query import select
from pyoq.query.execution import StreamPolicy

from application.generated_database.tables import ACCOUNTS


def export_accounts(database: Database) -> None:
    query = (
        select(ACCOUNTS.ID, ACCOUNTS.EMAIL)
        .from_(ACCOUNTS)
        .order_by(ACCOUNTS.ID)
    )
    with database.stream(query, policy=StreamPolicy(batch_size=500)) as rows:
        for account_id, email in rows:
            write_export_row(account_id, email)

A stream owns one checked-out connection until its context exits. Do not leave the stream open while waiting on unrelated network work. Open a stream from the transaction object when its query must share that transaction.

Observe pool pressure

database.pool_stats is a point-in-time value:

Python
statistics = database.pool_stats
metrics.gauge("database.connections.open", statistics.open_connections)
metrics.gauge("database.connections.idle", statistics.idle_connections)
metrics.gauge("database.connections.in_use", statistics.checked_out_connections)

Choose maximum_size from the server connection budget. A process owns one pool, so the upper bound is processes * maximum_size. Leave capacity for migrations, administration, and rolling replacement. Increasing the pool does not increase database capacity.

When every connection is checked out, acquisition waits for checkout_timeout. ConnectionPoolTimeoutError means the pool remained saturated. Investigate long transactions, streams that did not close, slow queries, and pool sizing before adding an immediate retry.

Broken connections are discarded. Returned MySQL connections are rolled back and have their statement timeout cleared before becoming idle again.

Test the lifecycle and behavior

Use unit tests for application rules, compiler tests for SQL shape, and integration tests against a real MySQL server for driver and transaction behavior. Do not replace the integration layer with SQLite because its locking, types, generated identifiers, and transaction behavior differ.

Python
from application.repositories.accounts import AccountRepository
from application.services.accounts import AccountService


def test_registration_is_visible(mysql_database) -> None:
    service = AccountService(mysql_database)

    created = service.register("owner@example.test", "Owner")
    found = AccountRepository(mysql_database).find_by_id(created.id)

    assert found == created

Give the test session its own schema or database. Apply migrations, regenerate types in check mode, open one pool for the test process, and roll back or clean test rows between cases. Test pool closure separately by asserting a checkout after the lifecycle exits raises ConnectionPoolClosedError.

Production checklist

  • Keep the DSN in a secret store or environment variable.
  • Create one pool per process, after the process starts.
  • Close that pool from the same composition root that created it.
  • Give repositories QueryOperations, never a DSN or connection factory.
  • Put transaction boundaries in application services.
  • Use transaction-bound operations for every statement inside a transaction.
  • Bound pool checkout and statement execution.
  • Close streams promptly and monitor checked-out connections.
  • Run generation checks after schema changes and in CI.
  • Test MySQL-specific behavior against MySQL.

For awaited MySQL execution, use the same ownership model with the asynchronous factory, pool, executor, and AsyncDatabase. See Asynchronous execution. General sizing and cleanup behavior is in Connections and pools, and schema snapshots are covered in Snapshots and drift.
