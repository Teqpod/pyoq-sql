Running statements

Dialects

SQLite, PostgreSQL, and MySQL, and where they differ.

The same statement compiles differently for each backend. Where a dialect cannot do something, it refuses while you are building rather than emitting SQL the server will reject. A refusal is UnsupportedQueryError, raised at build time with the reason.

Every row below was taken from a running server, and a contract compiles each one against every dialect, so a claim here that is not true stops the build.

refused means PyOQ raises before the statement is sent. written by PyOQ means the dialect has no such operation and PyOQ writes it out of what the dialect does have, so one word means one thing on all three.

These are properties of the connection rather than of an operation.

MySQL applies max_execution_time to read-only statements only, so a timeout does not bound a write there.

Choosing one

Python
from pyoq.query.sqlite import SQLiteCompiler
from pyoq.query.postgres import PostgresCompiler
from pyoq.query.mysql import MySQLCompiler

Each takes a capabilities object, so you can describe a server that differs from the default, an older SQLite, a lower parameter limit, a MySQL without a feature:

Python
from pyoq.query.sqlite import SQLiteCapabilities

SQLiteCompiler(SQLiteCapabilities(nested_collections=False))

Placeholders

Each dialect binds parameters the way its driver expects: ? for SQLite, %s for PostgreSQL and MySQL. You never write a placeholder yourself, and values never reach the SQL text.

Running under Django is the exception worth knowing about: Django’s SQLite cursor takes %s and rewrites it, so PyOQ compiles format style on that connection. It is handled for you; it matters only if you are reading the compiled SQL and wondering why it differs.

Types that do not exist everywhere

A backend without a UUID type stores the hex form. Without an interval type, a duration is microseconds. PyOQ writes and reads whichever the backend uses, so your code passes a UUID and a timedelta regardless, see Column types.

Seeing the SQL

Python
compiled = SQLiteCompiler().compile(statement)
compiled.sql
compiled.parameters

Useful in a test: assert what a query compiles to without a database anywhere near it.
