Installing

The distribution, the extras, and what each one pulls in.

PyOQ is published as pyoq-sql and imported as pyoq.

With uv:

Terminal
uv add pyoq-sql

With pip:

Terminal
pip install pyoq-sql

uv add records it in pyproject.toml and the lockfile. To install into an environment without recording anything, uv pip install pyoq-sql takes the same arguments pip does.

A plain install has no dependencies at all. SQLite works immediately, because Python already ships it.

Extras

Everything else is opt in, so a project pulls in only the drivers it uses.

ExtraInstallsFor
postgrespsycopgPostgreSQL, synchronous and asynchronous
mysqlPyMySQLsynchronous MySQL
mysql-asyncPyMySQL, asyncmyasynchronous MySQL
djangoDjangothe Django integration
fastapifastapithe FastAPI integration
sanicsanicthe Sanic integration
tracingopentelemetry-apireporting statements to OpenTelemetry

Combine them as needed. Quote the name: a shell reads square brackets itself.

With uv:

Terminal
uv add "pyoq-sql[postgres,fastapi]"
uv add "pyoq-sql[django,mysql]"

With pip:

Terminal
pip install "pyoq-sql[postgres,fastapi]"
pip install "pyoq-sql[django,mysql]"

Nothing outside an adapter imports its extra. Installing [django] does not drag in a database driver, and a dialect is loaded only once a connection turns out to speak it.

Checking what you have

Inside a uv project:

Terminal
uv run python -c "import pyoq; print(pyoq.__version__)"
uv run pyoq --version

Or in an activated environment:

Terminal
python -c "import pyoq; print(pyoq.__version__)"
pyoq --version

The command line can also be run without installing PyOQ into the project at all, which is enough to read its help or check a version:

Terminal
uvx --from pyoq-sql pyoq --version

Python

3.11 and later. The typed builders lean on TypeVarTuple and modern union syntax, so earlier versions cannot express the API.

Type checkers

PyOQ is checked under both mypy strict and pyright strict, and ships py.typed. If your project runs either, the generated code and everything you build from it are checked the same way.

Native and portable wheels

Supported platforms install a wheel containing the native hot-path kernels. Other platforms install the portable wheel and use the Python implementation. Neither wheel needs Rust on the target machine.

Selection is automatic. Set PYOQ_RUNTIME=python to require the portable implementation, or PYOQ_RUNTIME=native to fail immediately when the native extension is unavailable. Performance explains what the native core accelerates.
